# Фронтенд — Автосервис (запись на услуги)

SPA на React 18 + Vite (JavaScript) для API из соседней папки `back/`.
Без UI-библиотек и TypeScript: чистый CSS с переменными, react-router для
маршрутов, fetch для запросов.

## Технологии

- **React 18** + **react-router-dom 6** — SPA-роутинг с защитой маршрутов по ролям
- **Vite 5** — dev-сервер (порт 3000, совпадает с CORS бэкенда) и сборка
- **Чистый CSS** — дизайн-токены в `:root`, файлы по слоям: `global.css` (базовые
  стили и контролы), `components.css` (бейджи, тосты, модалки, таймлайн),
  `layout.css` (шапка/меню/подвал), `pages.css` (страницы)
- **vitest** — юнит-тесты утилит (слоты записи, форматирование денег/длительности, статусы)

## Запуск

```bash
# 1) бэкенд (см. back/README.md): docker compose up --build или uvicorn на :8000

# 2) фронтенд
cd front
npm install
npm run dev        # http://localhost:3000

# тесты и сборка
npm test
npm run build      # dist/ для продакшена
```

Адрес API настраивается переменной `VITE_API_URL` (см. `.env.example`);
по умолчанию — `http://localhost:8000/api`.

## Роли и экраны

| Роль | Экраны |
|---|---|
| Гость | витрина, вход, регистрация |
| `client` | запись (услуга → мастер → слот), мои заявки, карточка заявки |
| `employee` | расписание с фильтрами, приём заявки, доп. расходы |
| `admin` | все записи + отмена, сотрудники (CRUD), услуги (CRUD), прайс (CRUD) |

Роли приходят в JWT и в ответе `POST /auth/login`; маршруты защищены на клиенте
(бэкенд проверяет права повторно на каждый запрос).

## Токен доступа

`POST /auth/login` возвращает `{access_token, user}`. Токен хранится в
`localStorage` (`as_token`), данные пользователя — рядом (`as_user`), чтобы после
перезагрузки страницы не ждать `GET /users/me`. Кажди запрос добавляет заголовок
`Authorization: Bearer <token>`; при ответе `401` клиент разлогинивается, и
guard отправляет пользователя на страницу входа. Refresh-токен в текущей схеме
не используется — срок жизни access-токена настраивается на бэкенде
(`ACCESS_TOKEN_EXPIRE_MINUTES`, по умолчанию 60 минут).

## Особенности, о которых стоит знать

- **Рабочие часы** (09:00–19:00) и шаг сетки слотов (30 мин) — константы
  `src/config.js`: API бэкенда не ограничивает время записи, он только проверяет
  пересечения и возвращает занятые интервалы сотрудника.
- **Занятость и часовые пояса:** бэкенд хранит время в UTC и фильтрует день
  `GET /employees/{id}/busy?day=...` по UTC-дате. Слоты строятся в локальной зоне
  браузера, занятые интервалы конвертируются корректно; пограничные случаи
  возможны только для визитов около полуночи UTC (для автосервиса с часами
  работы 09:00–19:00 по Москве это не встречается). Пересечения дополнительно
  страхует сервер: при 409 форма перезапрашивает занятость.
- **Удаление услуг/сотрудников:** если объект используется в записях, бэкенд
  возвращает 409 с пояснением — интерфейс показывает этот текст в уведомлении.
- **Статусы заявки:** `new` → `accepted` → `completed` → `paid` — штатную цепочку
  ведёт сотрудник (принять → отметить выполненной → отметить оплату);
  `cancelled` — терминальный, отменяет администратор, но только записи в `new`
  или `accepted` (выполненную и оплаченную отменить нельзя). Таймлайн в карточке
  показывает пройденные шаги и текущий. После `completed` итоговая сумма
  зафиксирована: добавить доп. расход больше нельзя (бэкенд отвечает 409).
